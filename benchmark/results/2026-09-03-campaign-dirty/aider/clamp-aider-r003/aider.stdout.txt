Looking at the code and the test cases, I can see the bug in the Clamp 
function. 



The current implementation:

- Returns `hi` when `x < lo` 

- Returns `lo` when `x > hi`

- Returns `x` when `lo <= x <= hi`



This is incorrect for clamping to the inclusive [lo, hi] interval. When x is 
outside the bounds, it should return the nearest bound (lo if x < lo, hi if x >
hi), not the opposite bound.



Looking at the test cases:

- `{-1, 0, 10, 0}`: x=-1 < lo=0, should return lo=0

- `{11, 0, 10, 10}`: x=11 > hi=10, should return hi=10  

- `{5, 0, 10, 5}`: lo=0 ≤ x=5 ≤ hi=10, should return x=5

- `{0, 0, 10, 0}`: lo=0 ≤ x=0 ≤ hi=10, should return x=0



The fix is to return the bounds themselves instead of swapping them.
