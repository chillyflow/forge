## Semantics checked

- **Current authorization remains separate from history.** `candidate_control` uses `cp->passed` for current PASS; the main loop first compares that snapshot with current inputs and destroys it on mismatch. A historical passing summary alone cannot authorize final. Matching complete failure yields FAILED; changed inputs yield UNVERIFIED.
- **The new boolean has a narrow lifecycle.** `latest_validation_passed` is zero-initialized with the checkpoint and updated with the retained complete result, input hash and validation ID. Incomplete checks do not overwrite that tuple. Reusing an unchanged passing snapshot records a generic historical pass observation rather than an old “Call final now” instruction.
- **Incomplete evidence stays distinct.** `validated` still requires stable snapshots, complete evidence and commands; missing/denied/unstable checks cannot become current PASS. The existing incomplete-attempt record remains separate from the last complete diagnostic. The new FAILED label can accurately describe the retained complete failure even if a later incomplete attempt exists; it does not manufacture success.
- **Only checkpoint operational prefixes are removed.** Retaining `result.summary` removes the checkpoint's “NOT PASSED”/“Call final now” wrapper from mandatory historical memory. Arbitrary diagnostic text, including gofmt advice inside a summary, remains quoted under the historical-input label. That is the intended scope, not a claim that every imperative in diagnostics is stripped.
- **Delta memory now describes arguments.** `yyjson_val_write(args)` excludes top-level `assistant_content`; the record includes actual tool name/call ID and a bounded argument excerpt. Source strings inside arguments remain source data, and long edits may still be excerpted. Full tool-call events, raw ACTION history and edit artifacts preserve original evidence on normal execution; native pairing logic is unchanged.
- **Allocation failures fail closed.** Arguments, compressed excerpt and temporary buffer are freed on both paths. The old delta is freed only after a replacement is ready. A failed allocation returns memory status and stops further inference; the already emitted raw tool-call journal and edit artifacts remain available. There is no new use-after-free or double-free found. Existing validation allocation failures similarly terminate rather than publish a partially retained success to another prompt.

## Coverage to complete before qualification

The added tests exercise matching failure, changed-input historical failure, current pass, argument-only delta memory, raw prose retention, complete message pairs and related edits after history omission. Two important state transitions are not asserted by those additions. These are coverage recommendations, not observed defects in the reviewed implementation.

1. **A real PASS followed by external mutation before the next prompt.** Use the existing synchronous `forge_agent_run` event callback: `fg_session_emit` invokes it after flushing an event. Mutate once on `candidate_checkpoint` where `data.passed=true`. Do not use `validation_result`, which can run before the candidate's final snapshot and test a different condition. The next loop iteration must invalidate `cp->passed` before choosing schema and control text.

   The existing `tests/unit/test_verification.c` target is a suitable home: it already has deterministic self-copied Go/gofmt helper executables and a Go fixture, so no new CMake target or external Python dependency is needed. A dedicated agent fixture can reuse those helpers and account for its additional session/script in cleanup. Native script: change `fixture.txt`, validate, read `fixture.txt`, validate, final. In the first passing-checkpoint callback, overwrite `fixture.txt` once. At prompt 3 assert current UNVERIFIED, historical PASSED, no old checkpoint “Call final now” prefix, and ordinary repair tools available. The later complete validation should authorize final. This avoids subprocess timing and filesystem-watcher races.

2. **Complete failure followed by an incomplete check.** Extend the bounded integration case with eight scripted actions: make `value()` return 0; validate (complete failure ID 1); replace it with a function that creates `marker.txt` during the test and returns 2; validate (assertion passes, but snapshot mutation prevents assessment); read; replace with a clean return-2 function; validate; final. The protected test stays unchanged. At prompt 5 assert current UNVERIFIED, historical failed ID 1 and its `AssertionError` retained, separate incomplete ID 2, and no current PASS. Creating the marker inside the function makes the validation-time mutation deterministic. The existing mutation test checks rejection but not these new retained-record labels.

Memory-failure paths were inspected, not fault-injected. Normal integration success will not prove those paths. Run the appropriate existing tests after the coordinated build; no conclusion here depends on an unperformed run.
