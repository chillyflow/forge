### NOTES

- Q2 answer: summary.c is not on the agent loop. forge_repo_summary_prepare/store/generate appear only in src/cli/main.c:599 and tests (grep over src/). Generation happens on demand via `forge summarize`; the cache key is recipe_hash + dependency_hash (summary.c:782-788), not the generation; there is no per-turn repeat and nothing here blocks the loop.
- Q3 answer: the repository-map prompt segment is built by forge_repo_summary (repo.c:1886-1898), a files-table listing (LIMIT 80), added once at agent.c:2397-2398 (priority 40, not pinned) and refreshed on observed changes (agent.c:549-553) and after stall validation (agent.c:463-466). Per-render cost is only re-rendering the stored text (context.c:637); the SQL runs per refresh, not per render.
