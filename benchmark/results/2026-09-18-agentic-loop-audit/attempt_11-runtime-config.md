- Baselines: no retained measurement exists for config parse, hardware probe, event-log overhead, or startup index time as such. The retained artifacts that bear on this domain are: benchmark/results/2026-09-11-capability/*/environment.json (host: RTX 5090 Laptop, 23.89 GiB VRAM total / 22.61 GiB free; 31.43 GiB RAM total / 21.89 GiB free; 24 logical CPUs) with docs/plans/agent-performance-avenues.md:114-120 (model qwen3moe, 48 layers, 17.28 GiB of tensors, KV 98,304 bytes/token f16); docs/plans/agent-performance-avenues.md:122-141 (f16/q8_0/q4_0 KV table and the 5.11 GiB spare figure); benchmark/results/2026-09-09-agent-loop-all-green/README.md:23-24 (11 runs at 14,348-15,214 segment tokens against a 14,336-token capacity). Claims 1 and 2 use these as inputs and are computed, not re-measured.
- Self-refuted before filing: expected a duplicated startup scan or repeated git calls; monitor.c:183 is the only full scan at run start, the first poll with wait_ms=0 does not rescan, and git is spawned once per full scan (repo.c:1196) or once per <=256-path delta batch (repo.c:1288). Also expected arena high-water growth to be unbounded; it is capped at 64 MiB by construction (agent.c:224) and reset per turn.
- Cross-ref: the per-scan double hashing of every unchanged file (fnv + SHA-256 + UTF-8 validation, repo.c:687-693) is unit 09's drafted finding (attempt_09-repo-retrieval-recovered.md) and is not refiled here. Scale on this repo, measured read-only: 79,193 tracked paths, 1.78 GiB total, of which 30,983 files carry an eligible extension (repo.c:592-598 includes .md/.json/.toml), so every full scan reads and hashes that eligible set.
- Arena coverage (question 4): the generation arena serves only the action-response parses (agent.c:2647, agent.c:3117); the per-turn prompt buffer (fg_buf), tool-output buffers (fg_process) and event JSON are malloc/free with per-turn lifetime - inherent, not a defect, but no reuse pool exists for them.
- fg_buf_printf formats twice and allocates a temporary per call (util.c:76-98); call sites are per-turn/per-event (38 references in agent.c), not per-token, and there is no measured baseline, so it is not filed.
- Metrics JSON (question 3): fg_metrics_json builds about 60 fields once per session (session.c:78-153) and fg_session_finish then emits it as an event, which parses and deep-copies it again (session.c:155-162); once per run, negligible.
- plan->draft_enabled is reported (main.c:423) but never set (always false) - matches the no-draft design; not filed.
- The planner budgets GPU 0 only and caps unified memory by RAM (hardware.c:528-535); documented in docs/CONFIG.md:172-176, deliberate, not filed.
- Discrepancy for the parent, outside this domain: the BRIEF cites benchmark/results/2026-09-17-judge-rerank/SUMMARY.md as MATERIAL; that file reads NOT MATERIAL (survival 71.2 percent vs 72.5 percent off). The MATERIAL verdict is in benchmark/results/2026-09-17-judge-rerank-v2/SUMMARY.md.
- Uncertainty: free VRAM at run time varies; claim 2's computed reduction uses the retained 22.61 GiB free measurement and holds for f16 while free VRAM stays below 23.48 GiB (i.e. always, given 23.89 GiB total). q8_0 at 16384 has only 69 MiB of budget slack, so a busier desktop can flip that alternative back to a reduction.
- Files skipped: none of the six scope files was skipped; each was read in full. repo.c, monitor.c, llama_backend.c, inference.c, config.h and the two plan docs were read only where the questions required.
